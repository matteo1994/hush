# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`hush` is a placeholder-swap credential proxy for AI coding agents: a child process only ever sees random placeholders in its env, and a loopback HTTP proxy swaps the placeholder for the real API key on the wire, only when the request is going to that secret's bound host. See README.md for the full design and threat model. Scope is deliberately narrow: static HTTP header credentials only (no DB creds, SSH, or request signing like SigV4).

## Commands

```bash
cargo build                 # debug build
cargo build --release
cargo fmt
cargo clippy --all-targets -- -D warnings
cargo test                  # unit tests, in-process TLS end-to-end tests, and tests/ driving the built binary
cargo test <name>           # run a single test by name filter
```

Fuzzing (`fuzz/`, cargo-fuzz, not run in CI): `src/lib.rs` exists only so the targets can reach `proxy::fuzzing`, which is built only under `cfg(fuzzing)`. Targets: `request` (head parsing, request framing, chunked bodies, target resolution), `response` (`relay_response` through a `Scrubber`; no value may reach the client within one response) and `scrub` (any values, any split of the stream). Run from `fuzz/` with `cargo fuzz run <target> corpus/<target> seeds/<target> -- -dict=http.dict -max_total_time=300` (`corpus/` is the untracked working corpus, `seeds/` the tracked starting inputs); on macOS with MacPorts or Homebrew compilers on `PATH`, set `CC=/usr/bin/clang CXX=/usr/bin/clang++` or libFuzzer fails to build. A crash lands in `fuzz/artifacts/`; turn it into a unit test before fixing it.

CI (`.github/workflows/ci.yml`) runs `cargo fmt --check`, the clippy line above and `cargo test --locked` on Linux only (macOS minutes bill at 10x on a private repo, so test macOS locally before a PR), using the toolchain from `rust-toolchain.toml`, plus `cargo deny --locked check advisories` (RustSec advisories against `Cargo.lock`; ignores, each with its reason, in `deny.toml`). CI also runs weekly, so a new advisory shows up without a PR; fix one with `cargo update -p <crate>` where an upgrade exists, and ignore it in `deny.toml` only with a reason it doesn't reach hush.

Versioning: `hush --version` prints the `Cargo.toml` version plus the commit it was built from, e.g. `hush 0.1.3 (93db286 2026-10-10)`, with `-dirty` after the hash for a tree with uncommitted changes (`build.rs` sets `HUSH_VERSION`). Don't bump the patch version or edit `CHANGELOG.md` in a PR: the `bump` job in `ci.yml` runs `.github/scripts/bump-version.sh` after a merge to master, once `lint` and `test` have passed, which bumps the version, adds a `CHANGELOG.md` section listing the merged commits' subjects, commits both as `Release X.Y.Z` and tags `vX.Y.Z`. So the squash-merge subject is the changelog line: write it as a sentence a user would understand. For a minor or major release, change `version` in `Cargo.toml` (and `Cargo.lock`) in the PR; the job then releases that version instead of bumping. Two cases are not a release: a merge that touches nothing under `src/`, `Cargo.toml`, `Cargo.lock`, `build.rs` or `rust-toolchain.toml` (its subject shows up in the next release's entry), and a run that master has already moved past (the newer commit's run releases both). After a releasing merge master has a second commit, so pull before branching. The sibling project `mile` uses the same script and job; keep the two in step. Pushes made with the workflow token don't trigger other workflows, so anything that should happen on a release has to be a later job in `ci.yml`.

Toolchain is pinned to a stable release via `rust-toolchain.toml` (rustup), so a new clippy lint can't fail CI with no code change and anyone with rustup builds with what CI tests; move it forward by hand, in a PR of its own that fixes whatever the newer clippy flags. Nothing needs nightly except `cargo fuzz`, so `fuzz/rust-toolchain.toml` pins a dated nightly of its own. Unix-only (`PermissionsExt`, `ExitStatusExt`, `libc` signals). Rust edition 2024.

`tests/run.rs` runs `hush run` end to end: a vault in a temp `HOME`, a child shell using curl through the proxy, and upstream servers on 127.0.0.1 that record what they receive. It covers the swap, Ctrl-C, exit codes and the run-dir sweep. Manual end-to-end testing without interactive prompts: set `HUSH_PASSPHRASE` (used by every command that opens the vault) and `HUSH_SECRET_VALUE` (used by `secret add`). They operate on the real vault at `~/.config/hush/`, and there is no config-dir override, so point `HOME` at a throwaway directory such as `target/e2e`. `hush run` strips both variables from the child, so a nested `hush secret ...` inside it has to prompt, and fails with "no terminal" when there is none.

## Architecture

Single binary, no background process. Each command opens the vault itself.

- **CLI** (`main.rs`): `init`, and `secret add/bind/rm/ls`, which load the vault with the passphrase, mutate it, and `save_vault` it again (writes `vault.age.tmp`, then renames). Each takes `--profile NAME` (`vault::check_profile`) to work on that profile's entries instead of the unprofiled ones; `rm` drops a profile with its last entry, and `ls` marks each entry's profile, or with `--profile` lists what a run with it would get. `profile use NAME` maps the project (`names::project_dir`: the git root, else the current directory; or `--dir`), canonicalized, to a profile that exists in the vault, and points out that profile's mappings to directories that no longer exist without removing them (an unmounted volume looks the same); `profile use --none` removes a mapping (`--dir` of a gone directory is resolved through its deepest existing ancestor, to match the stored spelling), `secret rm` of a profile's last entry keeps its mappings, and `profile ls` lists profiles with their mapped directories. Each load-modify-save holds `lock_vault` (an exclusive lock on `vault.lock`, a separate file because the rename replaces `vault.age`); reads don't lock. Mutations print what will change before prompting. Any prompt (`read_secret`), `secret ls` included, first warns once when `HUSH_ACTIVE` is set, i.e. when running inside `hush run`, where an agent that started the command can read the terminal (`warn_if_inside_run`). `secret add` on an existing name lists its bindings and asks `[y/N]` on `/dev/tty` before the value prompt, unless `--force`; `secret bind` refuses a second binding for an env the secret already has (`SecretEntry::add_binding`).
- **Names** (`names.rs`): `collect` merges, in order and deduplicated, the `_KEY` names from the nearest `.env` (searched upward to the git root; outside a repo only the current directory), every name in `~/.config/hush/global.env`, and `--secret` flags. Shell-style `export NAME=` is accepted. This only scopes which placeholders a run gets. It isn't a security boundary.
- **`hush run`** (`run.rs`): prompts only if `names::collect` returned any names. It loads the vault, `mint`s a `hush_ph_<32 hex>` placeholder per matched name into a `PlaceholderEntry` table (with `--profile`, or else the profile mapped to the nearest directory at or above the canonical cwd (`Vault::mapped_profile`, announced on stderr), from that profile's entry for the name, else the unprofiled one; a profile the vault doesn't have warns and falls back, and with no mapping found, every mapped directory with the project's name that no longer exists is warned about, since a moved project silently loses its mapping), and drops the vault, so only the named secrets stay in memory. Then it creates a `Mitm`, writes trust files into a private `RunDir` (`~/.config/hush/runs/<pid>/`, removed on drop; directories of runs whose pid no longer exists are swept at the next start), starts the proxy threads in-process, and spawns the child. After spawning it ignores SIGINT/SIGQUIT, so Ctrl-C reaches the child without killing the proxy. The child's exit code is passed through (`128+signal` if it was killed).
- **Proxy** (`proxy.rs`): forward proxy on `127.0.0.1:<random port>`, thread per connection. Plain HTTP (absolute-form URI or `Host` header) and intercepted HTTPS both go through `forward`, which sends one request upstream with hop-by-hop headers stripped and relays one response, each framed by `Content-Length`, chunked coding, or (responses only) the connection closing. Request framing is strict (`request_framing`, `chunk_size`): both `Transfer-Encoding` and `Content-Length`, `chunked` that isn't the single final coding, conflicting or non-digit lengths, and malformed chunk lines get a 400 and end the connection before anything goes upstream, so the proxy and the server can never disagree on where a request on a kept-alive connection ends. An intercepted HTTPS connection is kept alive: `handle_connect` pairs the client connection with one upstream TLS connection of its own and loops, so every request on it is parsed and substituted separately and the upstream connection is reused but never shared between clients (no pool, so a framing disagreement can only affect the client that caused it). Between requests `wait_for_request` polls both sockets and closes the client side as soon as the server drops the idle connection. The pair ends when either side sends `Connection: close`, the response is delimited by close, or anything fails. Plain HTTP stays one request per connection, sent with `Connection: close`. `CONNECT` to a target that some minted placeholder's binding matches (`is_bound`) is intercepted; any other `CONNECT` is a blind TCP tunnel that is never decrypted. Swapping (`substitute_placeholders`) only happens when the header name matches the binding's `header` (case-insensitive), the header value exactly equals `format` with `{value}` → placeholder, and the target host string equals the binding's host (case-insensitive; for HTTPS the target is the `CONNECT` authority, not the inner `Host` header). A binding's `host` may carry a port (`api.example.com:8443`, `127.0.0.1:3000`, `[::1]:3000`; `vault::split_host`), and a port it names must equal the target's. An upstream on this machine (judged by the connection, `Target::this_machine`: a loopback peer address, or one equal to the local address, as for the machine's LAN address) is matched differently: the binding must name an address and port equal to the socket actually connected to, whatever name the request used, since the child can listen on any port of this machine and on the other address family of a port (`localhost` is both `127.0.0.1` and `::1`). `secret add/bind` refuse a loopback binding that isn't an address with a port (`vault::check_host`, `vault::unusable_loopback`), and `hush run` warns about older bindings like that, which are never sent. Only connections where some binding matches (`is_bound`) are intercepted and scrubbed. The request must also name no other host (`names_only`, which compares names only): every `Host` header, at least one, and the authority of an absolute-form request target have to be the target host, because a server shared between sites, such as a CDN, routes on those and would deliver the real value to another site's origin. Plain HTTP to an upstream that isn't on this machine (`cleartext`) additionally needs the binding's `allow_http`. Otherwise the placeholder is forwarded verbatim — this silent pass-through is the core security property, don't turn it into an error. Requests to a bound host go out with `Accept-Encoding: identity`, and their responses pass through a `Scrubber` that replaces every real value with a same-length `HUSH_REDACTED***` marker (so framing stays valid), holding back the last `longest value − 1` bytes of each read so a value split across reads is still caught. Connection errors are never printed while the child runs (it owns the terminal); they are counted in an `ErrorLog` and `run` prints a summary after the child exits.
- **Hardening** (`harden.rs`): `main` first calls `harden::process`, which makes the process non-dumpable on Linux and, on macOS, refuses debugger attach (`PT_DENY_ATTACH`) and drops the soft core-dump limit to 0. `run::spawn` gives the child the original limit back (`restore_for_child`); `PR_SET_DUMPABLE` is reset by exec on its own.
- **TLS** (`tls.rs`): `Mitm` holds a per-run CA whose key lives only in memory, plus cached per-host leaf `ServerConfig`s and the upstream `ClientConfig` (system roots via `rustls-native-certs`, `ring` provider, HTTP/1.1 ALPN only). `write_trust_files` writes `ca.pem` and `ca-bundle.pem` (system roots + CA) into the run's directory. Leaves need an Authority Key Identifier and ≤398-day validity, or OpenSSL strict mode (Python 3.13+) and Apple clients reject them.
- **Vault** (`vault.rs`): age scrypt-passphrase-encrypted JSON of `name → SecretEntry { value, bindings }` (the unprofiled entries), plus `profiles: profile → { secrets: name → SecretEntry }`, and `directories: canonical path → profile`, both left out of the JSON when empty so a vault without profiles is written exactly as before. The directory map lives in the vault, not the project, so redirecting a project to another profile takes the passphrase. `Vault::entry` and `find_binding` take a profile's entry for a name and fall back to the unprofiled one; a profile's entry replaces it whole, bindings included. Every vault type is `deny_unknown_fields`, so a vault written by a newer hush fails to load instead of losing fields on save (0.1.16 and earlier ignore unknown fields, so they drop profiles); a format change must stay additive, with serde defaults. Each `Binding` has `host` (optionally `host:port`; on this machine an address and port), optional `env`, `header` (default `Authorization`), `format` (default `Bearer {value}`), `allow_http` (default false). `find_binding` prefers an exact `--env` match, then falls back to an unscoped binding; a secret has at most one binding per env. Config dir and `runs/` are `0700`, the vault is `0600`.

### Child environment (`run::child_env`)

The parent env minus `HUSH_PASSPHRASE`/`HUSH_SECRET_VALUE`, plus:
- the placeholders;
- `HUSH_ACTIVE=1`, which makes a nested `hush run` refuse to start;
- with a proxy running: `HTTP(S)_PROXY` in both cases, `SSL_CERT_FILE`/`REQUESTS_CA_BUNDLE`/`CURL_CA_BUNDLE`/`GIT_SSL_CAINFO` pointing at the bundle, `NODE_EXTRA_CA_CERTS` pointing at the CA alone, and `NODE_USE_ENV_PROXY=1`.

## Invariants to preserve

- Real secret values must never enter a `hush run` child's environment, argv or stdout/stderr (`secret ls` prints bindings only).
- Every vault change must require the passphrase, and nothing may hand the passphrase or a decrypted vault to the child. That's what stops a child from rebinding a secret to a host it controls.
- Only bound hosts are ever intercepted, and the CA private key must never be written to disk.
